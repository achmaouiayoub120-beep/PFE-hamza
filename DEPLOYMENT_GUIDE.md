# Deployment Guide: UniNetwork to Vercel

This guide walks you through deploying UniNetwork to Vercel with a production PostgreSQL database.

## Prerequisites

- GitHub account with your repository
- Vercel account (free tier available)
- Neon PostgreSQL account (free tier available)
- Domain name (optional)

## Step 1: Prepare Your Repository

### 1.1 Create GitHub Repository

```bash
# Initialize git if not already done
git init

# Add all files
git add .

# Create initial commit
git commit -m "Initial commit: UniNetwork university social platform"

# Add remote and push
git remote add origin https://github.com/yourusername/uninetwork.git
git branch -M main
git push -u origin main
```

### 1.2 Verify .env.example Exists

Make sure `.env.example` has all required variables (no secrets):

```
DATABASE_URL="postgresql://user:password@localhost:5432/uninetwork"
NEXT_PUBLIC_UPLOADTHING_APP_ID="your_app_id"
UPLOADTHING_SECRET="your_secret"
NODE_ENV="production"
NEXT_PUBLIC_APP_URL="https://your-domain.com"
```

## Step 2: Set Up Neon PostgreSQL Database

### 2.1 Create Neon Account

1. Go to https://neon.tech
2. Sign up with GitHub or email
3. Create a new project
4. Choose region closest to your Vercel deployment region

### 2.2 Get Connection String

1. In Neon dashboard, click "Connection String"
2. Copy the PostgreSQL connection string
3. Should look like: `postgresql://user:password@ep-xxx.us-east-1.neon.tech/database?sslmode=require`

### 2.3 Test Connection Locally (Optional)

```bash
# Update .env.local temporarily
DATABASE_URL="postgresql://neon_user:password@ep-xxx.us-east-1.neon.tech/neon?sslmode=require"

# Run migrations locally
npx prisma migrate deploy

# Verify connection
npx prisma db execute --stdin < check.sql

# Revert to local SQLite when done
DATABASE_URL="file:./dev.db"
```

## Step 3: Deploy to Vercel

### 3.1 Connect GitHub Repository

1. Go to https://vercel.com/new
2. Click "Import Git Repository"
3. Paste your GitHub repository URL
4. Click "Import"

### 3.2 Configure Project

**Framework Preset**: Next.js (auto-detected)

**Build Settings**:
- Build Command: `next build` (default)
- Output Directory: `.next` (default)
- Install Command: `npm ci` (default)

**Root Directory**: `.` (leave as is)

### 3.3 Add Environment Variables

In the "Environment Variables" section, add:

#### Production Variables

```
DATABASE_URL = postgresql://user:password@ep-xxx.us-east-1.neon.tech/database?sslmode=require
NODE_ENV = production
NEXT_PUBLIC_APP_URL = https://your-domain.vercel.app
NEXT_PUBLIC_UPLOADTHING_APP_ID = your_app_id (optional)
UPLOADTHING_SECRET = your_secret (optional)
```

**For Multiple Environments**:
- Set Production, Preview, and Development variables separately if needed
- Click "Decrypt" next to each variable in the dashboard to verify

### 3.4 Deploy

1. Click "Deploy"
2. Wait for build to complete (usually 2-3 minutes)
3. Vercel will provide your deployment URL

## Step 4: Run Database Migrations on Production

### 4.1 Option A: Using Vercel CLI (Recommended)

```bash
# Install Vercel CLI
npm i -g vercel

# Connect to your project
vercel link

# Deploy with environment access
vercel env pull  # Downloads prod environment variables

# Run migrations with production database
npx prisma migrate deploy

# Verify migration completed
npx prisma db execute --stdin < verify.sql
```

### 4.2 Option B: Using Vercel Dashboard

1. Go to Vercel Dashboard → Your Project
2. Go to Settings → General
3. Scroll down to "Git" section
4. Note the deployment URL

Then manually set the DATABASE_URL in production if needed.

### 4.3 Verify Database Connection

Create a test file `check-db.js`:

```javascript
const { PrismaClient } = require('@prisma/client');
const prisma = new PrismaClient();

async function main() {
  const users = await prisma.user.count();
  console.log(`Connected to database. Users: ${users}`);
}

main()
  .catch(console.error)
  .finally(() => process.exit(0));
```

Then run:
```bash
node check-db.js
```

## Step 5: Configure Custom Domain (Optional)

### 5.1 Connect Domain to Vercel

1. In Vercel Dashboard, go to Settings → Domains
2. Enter your domain name
3. Vercel shows DNS records to add

### 5.2 Update DNS Records

Add Vercel's DNS records to your domain provider:

1. Go to your domain provider (GoDaddy, Namecheap, etc.)
2. Find DNS settings
3. Add CNAME or A records as shown in Vercel
4. Wait for DNS propagation (5 minutes to 48 hours)

### 5.3 Verify Domain

1. Vercel will automatically verify when DNS is configured
2. Check project settings for HTTPS status
3. SSL certificate auto-generated by Vercel

## Step 6: Set Up Continuous Deployment

### 6.1 GitHub Integration (Already Done)

- Every push to `main` branch triggers production deployment
- Pull requests create preview deployments automatically
- Deployments are atomic and instant rollback available

### 6.2 Protected Branches (Recommended)

1. Go to GitHub repository settings
2. Go to Branches → Add rule
3. Create rule for `main` branch:
   - Require pull request reviews
   - Require status checks to pass (Vercel)
   - Dismiss stale pull request approvals

## Step 7: Monitoring & Maintenance

### 7.1 Monitor Deployments

1. **Analytics**: Vercel Dashboard → Analytics
   - View request counts, response times, bandwidth
   - Monitor bot traffic and error rates

2. **Edge Logs**: Vercel Dashboard → Edge Logs
   - See real-time request logs
   - Debug issues in production

### 7.2 Monitor Database

1. **Neon Dashboard**: View query performance
2. **Connection Pool**: Monitor active connections
3. **Backups**: Neon auto-backs up database

### 7.3 Error Tracking

1. Add Sentry for error monitoring (optional):
   ```bash
   npm install @sentry/nextjs
   ```

2. Configure in `next.config.ts`

### 7.4 Performance

1. Monitor Core Web Vitals in Vercel Analytics
2. Use Next.js built-in Performance metrics
3. Optimize images and code splitting automatically

## Step 8: Scaling Considerations

### 8.1 Database Performance

As user base grows:

1. **Enable Neon autoscaling**:
   - Neon automatically handles connections
   - Monitor compute metrics in dashboard

2. **Add indexes** for frequently queried fields:
   ```prisma
   model Post {
     @@index([authorId])
     @@index([createdAt])
   }
   ```

3. **Implement pagination** for large datasets:
   ```typescript
   const posts = await prisma.post.findMany({
     take: 20,
     skip: offset,
     orderBy: { createdAt: 'desc' }
   });
   ```

### 8.2 File Storage

For production file uploads:

1. **UploadThing**: Recommended for Vercel
   - Sign up at uploadthing.com
   - Get API keys
   - Set environment variables
   - Auto-scales with usage

### 8.3 Increasing Usage Limits

1. **Vercel Pro** ($20/month):
   - Faster builds
   - More edge functions
   - Advanced analytics

2. **Neon Pro** ($14/month minimum):
   - Higher compute limits

## Troubleshooting

### Build Fails

```
Error: ENOENT: no such file or directory
```

- Check `.env.example` has all required variables
- Ensure `.gitignore` doesn't exclude necessary files
- Verify `package.json` has all dependencies

### Database Connection Fails

```
Error: Can't reach database server at <host>
```

- Verify `DATABASE_URL` is correct in Vercel
- Check Neon database status
- Verify IP whitelist (Neon auto-allows Vercel IPs)
- Test with `prisma db execute --stdin`

### Migrations Fail

```
Error: P3001 - Migration already applied
```

- Verify local migrations match production
- Use `npx prisma migrate status` to check state
- See `MIGRATION_GUIDE.md` for recovery options

### Environment Variables Not Loading

- Go to Vercel Settings → Environment Variables
- Ensure variables are set for correct environment
- Redeploy after adding variables
- Verify variable names exactly (case-sensitive)

## Rollback & Recovery

### Rollback to Previous Deployment

1. Vercel Dashboard → Deployments
2. Find previous stable deployment
3. Click on it → View details
4. Click "Promote to Production"
5. Old version is now live

### Database Rollback

```bash
# Check migrations
npx prisma migrate status

# Resolve failed migration
npx prisma migrate resolve --rolled-back migration_name

# Manually reset (development only)
npx prisma migrate reset
```
